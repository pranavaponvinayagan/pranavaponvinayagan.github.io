Real-Time TMS-EMG Acquisition & Control System

Research Intern · April to May 2026 · Real-time C++, device drivers, serial and TCP protocols

Two real-time C++ modules for RTXI on Xenomai Linux that replaced a non-real-time setup with programmatic TMS control and multichannel EMG acquisition for live human motor-evoked potential (MEP) experiments.

The Problem

MEP experiments pair a TMS pulse to the motor cortex with a recording of the muscle's response, so stimulation and recording have to line up precisely. The lab's previous setup wasn't real-time: TMS couldn't be controlled reliably from code, and EMG data couldn't be streamed into the experiment without lag. That made precise, repeatable experiments difficult and ruled out anything closed-loop.

The Solution

I built two separate RTXI modules, one for each device, so they could be developed, tested, and reused independently.

1. BiStimComm: TMS control driver

A serial communication driver for the Magstim BiStim² paired-pulse TMS stimulator.

  • State-machine architecture: each command moves through defined states, so the driver always knows what the device is doing and never sends a command out of order.
  • Checksummed protocol: every command packet is built with a checksum, and the device's response is verified before the next command goes out.
  • Hardware validation: I tested the driver on the bench with loopback testing to confirm timing and reliability before it ever connected to the stimulator.

2. TrignoStream: EMG acquisition module

A 16-channel acquisition module for the Delsys Trigno wireless EMG system.

  • Dual-socket TCP: separate command and data connections to the Trigno base station.
  • Non-real-time listener thread: all network I/O happens on its own thread, outside the real-time loop.
  • Wait-free handoff: data passes to the real-time loop through a wait-free buffer, so the loop never stalls waiting on the network.

Impact

Both modules run in the lab's real-time setup, so researchers can fire TMS directly from code and stream 16 channels of EMG into the same pipeline without lag during live experiments. The TMS control is also ready for closed-loop experiments in the future.

The biggest lesson from this project was to keep anything slow or unpredictable, like network I/O, completely out of the real-time loop, and to validate hardware communication on the bench before trusting it in an experiment.
